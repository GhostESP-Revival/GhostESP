Reference for the lora, mesh and meshcore commands. Setting up for the first time? Start with [First run](/latest/lora/getting-started/). Run lora help or help all for the live list on the device.
## Start, stop, status
Command |
What it does |
lora status |
Radio state, region, frequency, modem, TX power, companion mode, last error |
lora start / lora on |
Power Vext (Heltec), init the SX1262, join LongFast, begin RX/TX |
lora stop / lora off |
Stop RX, release the radio and Vext |
lora setup |
Interactive first-run wizard: region, channel, companion, start |
mesh |
Show what owns the radio, and the remembered boot choice |
mesh off |
Stop the active protocol |
## Protocol switching
One radio, one protocol at a time.
Command |
What it does |
mesh switch meshtastic |
Stop MeshCore, start Meshtastic, remember it |
mesh switch meshcore |
Stop Meshtastic, start MeshCore, remember it |
mesh on [protocol] |
Start the remembered protocol, or the one you name |
The remembered choice only changes after a protocol starts successfully, so a failed switch never leaves boot pointed at a dead radio.
## Boot auto-start
Auto-start is opt-in and remembers whether to start and which protocol.
Command |
What it does |
lora autostart |
Show the setting and the boot protocol |
lora autostart meshtastic |
Boot Meshtastic (needs a saved region) |
lora autostart meshcore |
Boot MeshCore (no region needed) |
lora autostart on / off |
Toggle auto-start, keep the current protocol |
mesh autostart &lt;meshtastic|meshcore|off&gt; |
Same thing from mesh |
meshcore autostart on|off |
MeshCore shortcut; on also selects MeshCore |
The radio starts late in boot, after the display and storage init, so it never starves system memory. Confirm what came up with mesh after a reboot.
## Messages and peers
Command |
What it does |
lora chat &lt;text&gt; |
Broadcast on the LongFast channel (default-key encrypted) |
lora chat |
List recent messages (aliases: lora send, lora messages) |
lora nodes |
List known nodes: ID, names, last heard, SNR/RSSI, hops |
lora nodeinfo [node] |
Advertise our name/key and request a reply |
lora dm &lt;node&gt; &lt;text&gt; |
Encrypted direct message; the peer key must be known |
lora pkinfo &lt;node&gt; |
Show the stored peer key and our own key |
lora channels |
Show the 8 channel slots, their roles and hashes |
## Radio settings
Changes apply on the next lora start unless noted.
Command |
What it does |
lora set region &lt;code&gt; |
Legal band plan; see [Regions](#regions) for all 24 codes |
lora region &lt;code&gt; |
Shorthand for lora set region |
lora set sf &lt;5..12&gt; |
Spreading factor; higher means longer range, lower rate |
lora set bw &lt;125|250|500&gt; |
Bandwidth in kHz; must match peers |
lora set cr &lt;5..8&gt; |
Coding rate, CR4/5 to CR4/8 |
lora set tx &lt;dBm&gt; |
TX power, clamped to the region limit |
lora set preset &lt;0..16&gt; |
Use a named Meshtastic preset instead of a custom modem |
lora set hop &lt;1..7&gt; |
Hop limit: how many relays a packet may cross |
lora set role &lt;0..12&gt; |
Device role: 0 client, 1 client mute, 2 router, 5 tracker, 6 sensor, 8 client hidden, 10 TAK tracker, 11 router late, 12 client base |
lora set offset &lt;MHz&gt; |
Frequency offset correction for a drifting crystal |
lora set ovrfreq &lt;MHz&gt; |
Hard frequency override, ignoring the region plan |
lora set chnum &lt;n&gt; |
Select the region frequency slot directly |
lora set txen &lt;on|off&gt; |
Enable or disable transmit (listen-only) |
lora set owner &lt;long&gt; &lt;short&gt; |
Advertised names (24 / 4 bytes), then send NodeInfo again |
lora set companion &lt;wifi|ble&gt; |
Transport for the companion app bridge |
## Phone app and companion
Command |
What it does |
lora ble on / off |
Start or stop the Meshtastic BLE service (Ghost-XXXX) |
lora ble status |
Link state, MTU, connected phone, nonce sync |
lora app |
Pairing hint: advertised name and channel hash |
lora companion wifi |
Bridge over Wi-Fi (keeps BLE free for scans) |
lora companion ble |
Bridge over BLE (shares the radio) |
lora setup |
Interactive first-run wizard |
Pairing steps are in [BLE App Link](/latest/lora/ble-app/).
## Diagnostics
Command |
What it does |
lora diag |
IRQ counters, TX queue, app FIFO, last RX metadata |
lora cad |
Five channel-activity trials with instantaneous RSSI |
lora reg &lt;hex&gt; [count] |
Read SX1262 registers; lora reg 0740 2 should show sync word 24 B4 |
lora pubkey |
Our Curve25519 public key |
lora pkselftest |
X25519, SHA-256 and AES-CCM known-answer tests |
lora pkitest &lt;node&gt; |
PKI encrypt and decrypt loopback against a peer (no TX) |
lora pktry &lt;hex&gt; |
Probe a captured frame against the PKI decrypt variants |
lora pki-regen |
Generate a new identity keypair |
Avoid lora pki-regen in normal troubleshooting: it replaces the identity key peers already stored, and they need a fresh NodeInfo before direct messages work again. The mesh selftest verb runs the crypto self test for whichever protocol is active.
## Active mesh verbs
The same actions without naming a protocol, applied to whichever one is running:
Command |
What it does |
mesh send &lt;text&gt; |
Send on channel 0 |
mesh messages |
Read received messages |
mesh dm &lt;peer&gt; &lt;text&gt; |
Direct message |
mesh peers |
Nodes (Meshtastic) or contacts (MeshCore) |
mesh channels |
List channels |
mesh app [on|off] |
BLE app link |
mesh selftest |
Crypto self test for the active protocol |
mesh meshtastic &lt;args&gt; / mesh meshcore &lt;args&gt; |
Run a protocol-specific command |
